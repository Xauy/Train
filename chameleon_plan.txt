2.1  Структура файла и зависимости
────────────────────────────────────
Импорты:
  from dataclasses import dataclass, field
  from typing import List, Optional
  from PyQt6.QtCore import QObject, QTimer, pyqtSignal

Файл не импортирует ни одну страницу UI напрямую — движок получает данные
через структуры (dataclass) и общается с UI исключительно через Qt-сигналы.
Это позволяет тестировать движок без запуска QApplication.


2.2  Dataclass-модели конфигурации
────────────────────────────────────
Эти классы описывают состояние, переданное в движок перед стартом симуляции.
Они же используются для JSON-сериализации (раздел 4).

  @dataclass
  class AxleDef:
      """Описание одной оси вагона. Координата offset_mm — от передней торцевой
      точки вагона вдоль направления движения."""
      offset_mm: float

  @dataclass
  class WagonDef:
      wagon_id: str
      name: str
      length_mm: float
      axles: List[AxleDef]   # минимум 2 оси; порядок — от передней к задней

  @dataclass
  class TrainConfig:
      train_id: str
      track_id: str
      s0_mm: float            # начальная продольная координата передней оси
      direction: str          # 'LeftToRight' | 'RightToLeft'
      wagons: List[WagonDef]  # порядок от головы состава к хвосту

  @dataclass
  class DKPConfig:
      sensor_id: str
      track_id: str
      s_mm: float             # положение датчика вдоль пути
      zone_mm: float          # полуширина зоны срабатывания
      sensor_type: str        # 'Fox' | 'Mongoose'
      enabled: bool
      direction_filter: str   # 'Any' | 'LeftToRight' | 'RightToLeft'

  @dataclass
  class ScenarioStep:
      duration_ms: int
      v0_mms: float           # начальная скорость шага (мм/с)
      accel_mms2: float       # ускорение (мм/с²)
      v_threshold_mms: float  # порог скорости (мм/с); 0 = без ограничения
      behavior: str           # 'LeftToRight' | 'RightToLeft' | 'Stop'

  @dataclass
  class SimConfig:
      train: TrainConfig
      dkps: List[DKPConfig]
      steps: List[ScenarioStep]
      dt_ms: int = 16         # шаг симуляции

2.4  Класс SimulationEngine
────────────────────────────
  class SimulationEngine(QObject):

      # Сигналы
      tick_updated   = pyqtSignal(object)   # payload: SimState
      dkp_triggered  = pyqtSignal(object)   # payload: DKPEvent
      step_changed   = pyqtSignal(int)      # payload: новый step_index
      sim_finished   = pyqtSignal()

      def __init__(self, config: SimConfig, parent=None):
          ...
          self._timer = QTimer(self)
          self._timer.setInterval(config.dt_ms)
          self._timer.timeout.connect(self._tick)

      # Публичный API
      def start(self)  → запускает _timer, сбрасывает состояние
      def pause(self)  → останавливает _timer без сброса
      def resume(self) → снова запускает _timer
      def stop(self)   → останавливает _timer, сбрасывает состояние
      def get_state(self) → SimState  (снимок текущего состояния)
      def get_event_log(self) → List[DKPEvent]  (все события за прогон)


2.5  Внутренний метод _tick()
──────────────────────────────
Вызывается каждые dt_ms миллисекунд. Алгоритм:

  Шаг А — Определить текущий ScenarioStep:
    Если step_index >= len(steps) → emit sim_finished(), остановить таймер.
    current_step = steps[step_index]

  Шаг Б — Применить кинематику:
    Если behavior == 'Stop':
      v = 0
    Иначе:
      Знак ускорения: sign = +1 (LeftToRight) или -1 (RightToLeft)
      v_new = v + sign * accel * dt_s
      Если v_threshold > 0:
        v_new = min(abs(v_new), v_threshold) * sign
      v = v_new

  Шаг В — Вычислить новую координату головы:
    s_head_new = s_head + v * dt_s

  Шаг Г — Обновить координаты всех осей:
    Для каждого вагона i и каждой оси j:
      Смещение оси от головы состава вычисляется как сумма длин всех предыдущих
      вагонов плюс offset_mm внутри текущего вагона.
      s_axis = s_head_new - total_offset_mm  (или + для RightToLeft)
    Сохранить предыдущие координаты (s_prev) перед обновлением.

  Шаг Д — Проверить срабатывание ДКП:
    Для каждого датчика d из config.dkps:
      Если not d.enabled → пропустить.
      zone_lo = d.s_mm - d.zone_mm / 2
      zone_hi = d.s_mm + d.zone_mm / 2
      Для каждой оси (i, j):
        s_prev = предыдущая координата оси
        s_curr = новая координата оси
        Пересечение: интервал [min(s_prev, s_curr), max(s_prev, s_curr)]
          перекрывается с [zone_lo, zone_hi]?
        Если да — определить направление прохода:
          direction = 'LeftToRight' если s_curr > s_prev, иначе 'RightToLeft'
        Применить direction_filter: если filter != 'Any' и не совпадает → пропустить.
        Создать DKPEvent, добавить в лог, emit dkp_triggered(event).

  Шаг Е — Обновить время шага и переключить при необходимости:
    step_elapsed_ms += dt_ms
    Если step_elapsed_ms >= current_step.duration_ms:
      step_elapsed_ms = 0
      step_index += 1
      emit step_changed(step_index)
      При переходе инициализировать v из v0 нового шага.

  Шаг Ж — Обновить SimState, emit tick_updated(state).


2.6  Граничные условия и валидация
────────────────────────────────────
Перед вызовом start() движок выполняет validate() → List[str] (список ошибок):
  — Каждый DKP с track_id должен существовать в списке путей.
  — s_mm каждого DKP должно быть в пределах [0, длина пути].
  — Состав должен содержать хотя бы один вагон с хотя бы двумя осями.
  — Список шагов сценария не должен быть пустым.
  — s0_mm не должно быть отрицательным или превышать длину начального пути.
Если validate() возвращает непустой список — start() бросает ValueError
с объединённым сообщением, UI перехватывает и показывает QMessageBox.

3.1  Решение по рендереру
──────────────────────────
Рекомендуется VisPy (pip install vispy).
Причины:
  — Предоставляет VisPy SceneCanvas, который является нативным QWidget.
  — Встроенная TurntableCamera для orbit-навигации мышью без дополнительного кода.
  — Готовые визуальные примитивы: Line, Box, Sphere, Text, Markers.
  — Рендеринг в offscreen-буфер через canvas.render() — нужно для MP4.

Альтернатива — pyqtgraph GLViewWidget, если VisPy создаёт проблемы с зависимостями.


3.2  Архитектура SceneWindow
─────────────────────────────
SceneWindow наследует QMainWindow (отдельное окно, не вкладка).

  class SceneWindow(QMainWindow):
      def __init__(self, engine: SimulationEngine, sim_config: SimConfig,
                   path_data: List[dict], parent=None):
          ...

Конструктор принимает готовый движок и данные путей/ДКП/состава.
SceneWindow не читает напрямую из виджетов страниц — только из структур.

Layout SceneWindow:
  ┌──────────────────────────────────────────────────────────────┐
  │  toolbar: [▶ Пуск] [⏸ Пауза] [⏹ Стоп]  │  шаг: 1/5        │
  │  [скорость: 0 мм/с · 0.0 км/ч]  [время: 00:00.000]         │
  ├──────────────────────────────────────────────────────────────┤
  │                                                              │
  │              VisPy SceneCanvas (центральный виджет)         │
  │                                                              │
  └──────────────────────────────────────────────────────────────┘

Toolbar реализуется через QToolBar (addToolBar).
Текстовые индикаторы — QLabel в том же toolbar.


3.3  Инициализация сцены
─────────────────────────
При создании SceneWindow выполняются:

  а) Создать vispy.scene.SceneCanvas(keys='interactive', show=False).
     Получить view = canvas.central_widget.add_view().
     Установить view.camera = 'turntable' (orbit мышью, zoom колёсиком).

  б) Нарисовать пути:
     Для каждого пути из path_data:
       Создать vispy.scene.visuals.Line(
           pos=[[x1,y1,z1], [x2,y2,z2]],
           color=(0.4, 0.6, 0.9, 1.0),
           width=3,
           parent=view.scene
       )
       Подписать: vispy.scene.visuals.Text(
           text=track_id, pos=[(x1+x2)/2, (y1+y2)/2, (z1+z2)/2],
           font_size=10, parent=view.scene
       )

  в) Нарисовать ДКП:
     Для каждого DKPConfig:
       Вычислить 3D-позицию: интерполировать точку на пути по s_mm.
         Для прямолинейного пути: pos = start + (s_mm / length) * (end - start)
       Создать vispy.scene.visuals.Markers(pos=[pos], size=12, ...).
       Сохранить ссылку в dict self._dkp_visuals[sensor_id] для последующей
       подсветки.

  г) Создать визуальные объекты для вагонов:
     Для каждого вагона — vispy.scene.visuals.Box(...) или набор из Lines.
     Сохранить в self._wagon_visuals[wagon_index].
     Позиции будут обновляться в _on_tick().

  д) Установить камеру так, чтобы вся сцена была видна:
     view.camera.set_range() после добавления всех объектов.


3.4  Подключение к движку
──────────────────────────
После создания движка подключить сигналы:

  engine.tick_updated.connect(self._on_tick)
  engine.dkp_triggered.connect(self._on_dkp_triggered)
  engine.step_changed.connect(self._on_step_changed)
  engine.sim_finished.connect(self._on_sim_finished)

  def _on_tick(self, state: SimState):
      # Обновить позиции вагонов и осей в сцене
      for i, wagon in enumerate(state.axes_by_wagon):
          # Вычислить 3D-позицию по s_mm через интерполяцию пути
          pos3d = self._s_to_xyz(wagon.s_mm, state.track_id)
          self._wagon_visuals[i].transform.translate = pos3d
      # Обновить HUD
      kmh = state.v_mms * 3.6 / 1000
      self._speed_label.setText(f"{state.v_mms:.0f} мм/с · {kmh:.1f} км/ч")
      self._clock_label.setText(self._fmt_time(state.t_ms))
      canvas.update()

  def _on_dkp_triggered(self, event: DKPEvent):
      marker = self._dkp_visuals.get(event.sensor_id)
      if marker:
          marker.set_data(face_color=(1.0, 0.65, 0.0, 1.0))  # amber
          # Сбросить цвет через 200 мс
          QTimer.singleShot(200, lambda: marker.set_data(face_color=normal_color))

  def _on_step_changed(self, idx: int):
      self._step_label.setText(f"Шаг: {idx+1}/{len(self._steps)}")

  def _on_sim_finished(self):
      self._btn_start.setEnabled(True)
      self._btn_pause.setEnabled(False)
      self._btn_stop.setEnabled(False)

4.2  Методы to_dict() / from_dict() на страницах UI
─────────────────────────────────────────────────────
Каждая страница реализует два метода:

  PathsPage.to_dict() → List[dict]
    Итерирует строки таблицы, возвращает список PathRecord.

  PathsPage.from_dict(data: List[dict])
    Очищает таблицу, добавляет строки из data.

  DkpPage.to_dict() → List[dict]
  DkpPage.from_dict(data: List[dict])

  SostavPage.to_dict() → dict   (TrainRecord + список WagonRecord)
  SostavPage.from_dict(data: dict)

  ScenarioPage.to_dict() → List[dict]   (список ScenarioRecord)
  ScenarioPage.from_dict(data: List[dict])

  ScenarioStepsDialog.get_steps() → List[dict]   (для ScenarioPage)
  ScenarioStepsDialog.set_steps(steps: List[dict])  (для редактирования)


4.3  Класс ProjectIO

  class ProjectIO:

      @staticmethod
      def save(path: str, pages: dict) -> None:
          """
          pages = {
              'paths':    paths_page,
              'dkps':     dkp_page,
              'sostav':   sostav_page,
              'scenario': scenario_page,
          }
          Собирает to_dict() со всех страниц, формирует финальный dict,
          сериализует в JSON с indent=2, пишет в файл UTF-8.
          """

      @staticmethod
      def load(path: str) -> dict:
          """
          Читает файл, проверяет version, возвращает dict с ключами
          paths, dkps, wagons, train, scenario.
          Бросает ValueError если версия не поддерживается или структура
          нарушена.
          """

      @staticmethod
      def validate_structure(data: dict) -> List[str]:
          """
          Проверяет целостность загруженных данных:
          — Все track_id в DKP присутствуют в paths.
          — s_mm каждого DKP ≤ длина соответствующего пути.
          — wagon_id в train.wagon_sequence присутствуют в wagons.
          Возвращает список строк с описанием ошибок (пустой = OK).
          """

5.3  MP4 + Timeline
─────────────────────
  def write_mp4(canvas: vispy.app.Canvas, engine: SimulationEngine,
                out_path: str, fps: int = 30) -> None

Алгоритм:
  — Запустить ffmpeg как subprocess с параметрами:
      ffmpeg -y -f rawvideo -vcodec rawvideo -s WxH -pix_fmt rgb24
             -r {fps} -i pipe:0 -vcodec libx264 -pix_fmt yuv420p {out_path}
  — Прогнать симуляцию заново (отдельный экземпляр SimulationEngine)
    с шагом dt_ms = 1000/fps (≈33 мс для 30 fps).
  — На каждом шаге: обновить сцену, canvas.render() → numpy array,
    записать bytes в stdin ffmpeg.
  — По завершении закрыть stdin ffmpeg, дождаться process.wait().

Timeline-файл ({out_path}.timeline.json):
  {
    "fps": 30,
    "events": [
      { "frame": 372, "t_ms": 12400, "type": "dkp_triggered",
        "sensor_id": "DKP_1", "axis_index": 3 },
      { "frame": 900, "t_ms": 30000, "type": "step_changed",
        "step_index": 1 }
    ]
  }
